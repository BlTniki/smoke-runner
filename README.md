# Smoke Runner

Личный Telegram-бот, который помогает постепенно увеличивать паузы между
эпизодами использования вейпа и видеть измеримый прогресс.

Продуктовые требования и архитектура согласованы. Реализация ведётся пакетами
из плана ниже; функциональный MVP уже умеет вести историю, соблюдать интервалы
и присылать отчёты.

## Текущий статус

Требования `1.2` и архитектура `1.2` согласованы. Этапы 0–5 завершены:
доменное ядро, SQLite persistence, закрытый Telegram-доступ и интерактивный MVP
с логированием, backfill, историей и настройкой интервала. Durable scheduler
отправляет одно уведомление при достижении актуального рубежа, восстанавливается
после рестарта и обновляет открытый дашборд раз в пять минут в течение получаса.
Ежедневные отчёты приходят в 09:00, воскресные недельные — следом за дневными и
с двумя PNG-графиками; незавершённая доставка продолжается после рестарта.
Следующий этап — backup/restore, варианты развёртывания и наблюдаемость.

## Локальная разработка

Требуется Python 3.14 и [uv](https://docs.astral.sh/uv/). Docker на рабочем
ноутбуке не нужен.

```bash
uv sync --locked
uv run python -m smoke_runner --help
make check
```

## Запуск бота

Docker не требуется. Создай Telegram-бота через BotFather и подготовь
конфигурацию:

```bash
cp .env.example .env
openssl rand -hex 32
```

В `.env` замени `SMOKE_RUNNER_BOT_TOKEN` и вставь результат последней команды в
`SMOKE_RUNNER_INVITE_PEPPER`. Затем:

```bash
uv sync --locked
uv run python -m smoke_runner
```

Миграции SQLite выполняются автоматически перед polling. Если администратор ещё
не привязан, приложение напечатает в терминал одноразовый код на 30 минут.
Отправь этот код боту в личном чате: Telegram ID привяжется автоматически, после
чего новый bootstrap-код больше не создаётся. Перезапуск до привязки заменяет
старый код новым.

Для автоматизированного деплоя ID по-прежнему можно заранее передать через
необязательный `SMOKE_RUNNER_ADMIN_TELEGRAM_USER_ID`. Администратор создаёт
обычные приглашения командой `/invite`, смотрит пользователей через `/users` и
отзывает доступ командой `/revoke <номер>`. Самого администратора эта команда
отозвать не позволяет. Тесты и `--help` не требуют настоящих секретов.
